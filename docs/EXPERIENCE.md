# Инженерный опыт

Это накопительная внешняя память. Новые записи должны содержать причину, решение, способ проверки и предел применимости.

## Исходная база: Prime Visuals

Источник: AGENTS.md проекта Prime-Script-FTAP, прочитан 2026-10-30. Это перенос выводов из документации, не новый аудит текущего runtime.

| Наблюдение | Практическое правило |
| --- | --- |
| Beam может пересоздаваться после смерти | Отслеживать актуальный объект, позднее появление и повторный запуск; одного присваивания недостаточно |
| Декоративный модуль или ColorPicker может не создаться | Предусмотреть рабочее значение по умолчанию и безопасные вызовы без падения всего меню |
| Несколько эффектов меняют одно свойство | Использовать учёт владельцев и восстановление слоёв, а не независимые несовместимые backups |
| Прямое вмешательство в камеру меняло чувствительность | Предпочитать совместимую штатную логику и обязательно проверять восстановление после отключения |
| SetValue-тесты пропустили баг кликов | Проверять обработчики ввода, координаты, фокус, порядок слоёв и дочерние popup |
| Профили сохраняют много небольших параметров | Стабильные ключи, валидация, резервные копии и coalescing записей |
| Симуляции дают ограниченную уверенность | Отдельно подтверждать реальный рендеринг, физику и серверное поведение |
| Закреплённый релиз загружает модули из тега | Публиковать полный набор зависимостей и проверять доступность файлов релиза |
